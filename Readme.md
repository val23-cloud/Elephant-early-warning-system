# Elephant Tracking System

An intelligent, near-real-time wildlife protection system designed to mitigate human-elephant conflict, map movement corridors, and issue early warnings to protect both elephants and local communities.

## 📡 System Architecture Overview
The system relies on a multi-layered telemetry and environmental data pipeline:
1. Data Acquisition: Tracking devices (GPS/GNSS Collars) deployed on elephants transmit localized telemetry.
2. Connectivity: Telemetry is forwarded via GSM, LoRaWAN, or Satellite IoT networks.
3. Database Layer: Core infrastructure powered by PostgreSQL utilizing the 'PostGIS' extension for spatial geometries, distance alerts, and automated geofencing.
4. Environmental Context: Integration with 'MOSDAC / INSAT' weather and environmental data (vegetation patterns, prelude of elephant paths, crop-to-wild transitions).
5. Cyclone & Early Warnings: Real-time satellite feeds track cyclones and severe weather anomalies to proactively save elephant herds from natural disasters.
6. Analytics & Alerts: An AI engine computes movement predictions to send automated alerts directly to Forest Officers, Railway networks, Farmers, and Villages.

## 🗄️ Database Schema & Relational Model
Dear team, please use the following schema definition to create the PostgreSQL tables:

### 1. elephants Table
Stores unique identity, biological tracking records, and baseline data.
* elephant_id (PK)
* tracking_code (UNIQUE)
* name, sex, birth_date
* health_status, created_at

### 2. tracking_devices Table
Tracks physical telemetry hardware mapped to individual animals.
* device_id (PK)
* elephant_id (FK -> elephants)
* serial_no (UNIQUE)
* fitted_at, removed_at, status

### 3. locations Table
Logs high-frequency time-series spatial data generated by hardware.
* location_id (PK)
* device_id (FK -> tracking_devices)
* recorded_at
* latitude, longitude
* speed_kmh, battery_pct

### 4. health_records Table
Maintains medical examination histories over time.
* health_id (PK)
* elephant_id (FK -> elephants)
* examined_at, condition
* temperature_c, weight_kg

### 5. alerts Table
Triggers notifications when spatial constraints are violated (e.g., Herd approaching railway track).
* alert_id (PK)
* elephant_id (FK -> elephants)
* location_id (FK -> locations)
* alert_type, severity, status

### 6. protected_zones Table
Defines geometric perimeters for geofencing.
* zone_id (PK)
* name, boundary (GEOGRAPHY)
